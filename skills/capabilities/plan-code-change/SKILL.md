# Plan Code Change

このCapabilityはWorkflowが内部Skillとして読み込んで使う。CodexのSkill探索対象へインストールせず、ユーザーの依頼から直接起動しない。

要求とコードベースの事実を、実装時に新しい設計判断が残らず、着手順が分かる変更計画へ変換する。ファイルは変更しない。

## Planning

1. 実現する振る舞い、対象外、互換性などの制約を確認する。
2. 影響範囲調査の結果を利用し、計画を左右する不足だけを追加調査する。
3. 既存パターンに沿う最小の方針を選び、主要な代替案がある場合は選定理由を示す。
4. 変更する責務、処理の流れ、外部から見える契約、失敗時の挙動を決める。
5. 変更を利用者から見た振る舞い、または独立して実装と検証ができる機能単位へ分け、依存関係とフィードバックの得やすさを基に実施順を決める。ファイルや技術レイヤーだけで分割しない。
6. 各機能単位について、実現すること、主な変更対象、前提となる単位、実装後の確認方法を決める。

ユーザーの意図を変える判断が必要なら計画を確定せず確認する。実装者が決められる局所的な詳細まで固定しない。

## Result

- 実現する振る舞いと対象外
- 採用する実装方針
- 実施順に並べた機能単位の実装計画。各単位に、実現すること、主な変更対象、前提となる単位、実装後の確認方法を含める
- 変更する責務と全体の処理の流れ
- インターフェースまたはデータへの影響
- 影響評価で判明した制約への対応
- 全体を通したテストと検証方法
- 未確定事項とリスク
