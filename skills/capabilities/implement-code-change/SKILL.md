# Implement Code Change

確定した変更方針を、既存の規約と設計を保った一貫した差分として実装する。

## Implementation

1. 実現する振る舞い、対象外、変更方針、制約、検証方法を確認する。実装を左右する情報が不足している場合は、推測で方針を決めず不足を返す。
2. 対象ファイルと作業ツリーを確認し、既存の未コミット変更や同種の実装を保つ。
3. 変更方針に沿って、必要最小限のコード、テスト、文書を変更する。要求されていない一般化やリファクタリングを加えない。
4. 実装中に方針と矛盾する事実が判明した場合は、影響が局所的なら整合する最小の調整を行い、振る舞いや範囲が変わる場合は実装を止めて判断を返す。
5. 差分を確認し、変更方針からの逸脱、意図しないファイル変更、明らかな未完了箇所がないかを確認する。

このCapabilityは実装結果の検証を完了したとは判定しない。テスト、静的検査、ビルドなどによる成功判定は呼び出し元へ委ねる。

## Boundaries

- 要求、公開インターフェース、保存データの互換性を独断で変更しない。
- ユーザーの未コミット変更を上書きまたは破棄しない。
- コミット、push、PR作成、デプロイ、リリースは行わない。
- 実装方針の再設計や、実装後の品質判定を引き受けない。

## Result

- 実現した変更
- 変更したファイルと責務
- 追加または更新したテストと文書
- 変更方針から調整した点と理由
- 実行が必要な検証
- 未解決の問題または停止理由
