# Draft Issue

このCapabilityはWorkflowが内部Skillとして読み込んで使う。CodexのSkill探索対象へインストールせず、ユーザーの依頼から直接起動しない。

ユーザーの意図を、実装者が作業を始められる開発Issueの構造化データへ変換する。内容の不足を推測で埋めず、渡された根拠と規約を区別して扱う。

## Input

- `userIntent`: 実現したい振る舞い、利用者、制約、対象外を含む依頼。
- `codebaseEvidence`: 任意の調査結果。確認済みのファイル、処理経路、既存テスト、制約だけを含める。未確認の推測は事実として扱わない。
- `repositoryConventions`: 任意のリポジトリ規約、既存パターン、検証コマンド。渡されなかった規約を創作しない。

## Drafting

1. 依頼から利用者に見える目的と変更の境界を抽出する。
2. コードベース根拠がある場合は、背景、対象範囲、受け入れ条件、検証、依存関係の根拠として反映する。根拠がない事実は「未確認」として断定しない。
3. リポジトリ規約を受け取った場合だけ、受け入れ条件や検証へ反映する。
4. タイトルは変更対象と結果が分かる簡潔な一行にする。タイトルと各リスト項目に改行を含めない。
5. 受け入れ条件は、完了を判定できる具体的な条件を少なくとも1つ作る。対象外は、依頼の範囲を広げないために明示する。

## Output

次の形のJSONだけを返す。値はすべてJSONの型に従い、Markdown本文、見出し、チェックボックス、コードフェンスは生成しない。

```json
{
  "schemaVersion": 1,
  "title": "変更対象と結果を示す一行",
  "background": ["現状または依頼の背景"],
  "goal": "利用者またはシステムが達成する結果",
  "acceptanceCriteria": ["完了を判定できる条件"],
  "scope": ["このIssueで変更する範囲"],
  "outOfScope": ["このIssueでは扱わない範囲"],
  "verification": ["実行する検証"],
  "dependencies": [],
  "risks": []
}
```

`dependencies` と `risks` は、渡された情報から確認できる場合だけ列挙する。情報がないことを理由に不要な依存やリスクを作らない。

## Boundaries

- ファイルを変更しない。
- JSON Schemaの検証やJSONからのMarkdown生成を実行しない。
- 外部サービス、ネットワーク、外部コマンドを使用しない。
- ラベル、重複Issue、リポジトリの状態、作成可否を判断しない。
- 受け取った根拠、規約、ユーザーの意図を超えて実装方式や作業範囲を決めない。
