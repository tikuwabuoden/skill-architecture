# Analyze Codebase

依頼された変更に必要な範囲だけを調査し、後続の設計判断に使える事実を示す。ファイルは変更しない。

## Analysis

1. リポジトリ固有の指示、作業ツリー、主要なマニフェストを確認する。
2. ユーザーが変更したい振る舞いから入口を特定し、関連する処理、データ、境界まで追跡する。
3. 同種の既存実装とテストを探し、従うべきパターンと不変条件を確認する。
4. 変更候補と影響範囲を、ファイルやシンボルなど確認可能な根拠と結び付ける。

調査範囲をリポジトリ全体へ無条件に広げない。確認済みの事実と推測を区別し、未確認の推測を実装前提にしない。

## Result

- 現在の処理経路
- 関連する実装とテスト
- 従うべき規約、パターン、不変条件
- 変更が及ぶ可能性のある範囲
- 実行可能な検証コマンド
- 解消できなかった不明点
