# Implement Feature

ユーザーが求める振る舞いを、既存リポジトリの規約と構造に沿って実装し、確認可能な状態まで進める。

## Workflow

1. リポジトリの指示、作業ツリー、関連する実装とテストを確認する。
2. 依頼と確認済みの事実から、実装後に満たす振る舞いと対象外を明確にする。
3. 結果を大きく変える判断だけをユーザーへ確認する。既存コードから決められる実装詳細は、その規約に合わせる。
4. 目的を満たす一貫した変更を実装する。無関係な変更や、要求されていない一般化を加えない。
5. 変更した振る舞いに対応する検証を選び、テストと差分確認を行う。未実施の検証は成功として扱わない。
6. 実装した結果、検証結果、残っている制約またはリスクを報告する。

## Boundaries

- 診断のみ、計画のみ、レビューのみを求められた場合は、それぞれの依頼範囲を越えて実装しない。
- コミット、push、PR作成、デプロイ、リリースは、ユーザーが明示的に依頼した場合だけ行う。
- リポジトリにある未コミットの変更はユーザーの作業として扱い、上書きまたは破棄しない。
- 要求を満たすために公開インターフェースや保存データの互換性を壊す必要が生じた場合は、実装前に確認する。

## Completion

完了時は、次を簡潔に示す。

- 実現した振る舞い
- 主な変更箇所
- 実行した検証と結果
- 未検証事項または残存リスク
